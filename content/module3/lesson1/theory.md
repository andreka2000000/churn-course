# Урок 3.1 — Baseline: Logistic Regression

## Что такое baseline

В ML есть золотое правило: **всегда начинай с самого простого решения**. Это называется baseline (базовая модель). 

Зачем это нужно:
1. **Точка отсчёта.** Если ты обучил сложную нейросеть, а она работает на 1% лучше логистической регрессии — возможно, нейросеть не стоит усилий.
2. **Проверка данных.** Если даже простая модель показывает хороший результат, значит, в данных есть сильный сигнал. Если простая модель выдаёт 50% (случайное угадывание), значит, с признаками что-то не так.
3. **Интерпретируемость.** С baseline легко объяснить бизнесу, почему модель приняла то или иное решение.

В нашем курсе baseline — это логистическая регрессия. Она простая, быстрая, но на удивление мощная для табличных данных.

## Как работает логистическая регрессия

Давайте начнём с обычной линейной регрессии. Она предсказывает число по формуле:

    y = w₀ + w₁·x₁ + w₂·x₂ + ... + wₙ·xₙ

Где `w` — это веса (коэффициенты), а `x` — наши признаки. Модель подбирает веса так, чтобы предсказание было как можно ближе к правде.

Проблема: линейная регрессия может выдать любое число, например `-5` или `+250`. А нам нужно предсказать **вероятность** оттока — число от 0 до 1.

Решение — **сигмоида** (sigmoid function). Это математическая функция, которая «сжимает» любое число в диапазон от 0 до 1:

    sigmoid(z) = 1 / (1 + e^(-z))

Свойства сигмоиды:
- Если z = 0, то sigmoid = 0.5.
- Если z очень большое положительное, sigmoid → 1.
- Если z очень большое отрицательное, sigmoid → 0.

Именно поэтому модель называется **логистической регрессией** — она выдаёт логистическую (S-образную) кривую.

## Вероятность и порог

Логистическая регрессия предсказывает **вероятность** того, что клиент уйдёт (число от 0 до 1).

Чтобы получить бинарный ответ (уйдёт / не уйдёт), нужно выбрать **порог** (threshold). По умолчанию порог = 0.5:
- p > 0.5 → предсказываем «уйдёт» (класс 1).
- p ≤ 0.5 → предсказываем «останется» (класс 0).

Порог можно менять. Если бизнес хочет ловить как можно больше уходящих (даже ценой ложных срабатываний) — порог снижают до 0.3. Если, наоборот, важно не беспокоить лояльных клиентов — порог поднимают до 0.7. Об этом подробнее в уроке 3.2.

## Веса и odds ratio

Каждый признак в логистической регрессии получает **вес** (коэффициент). Вес показывает, насколько сильно признак влияет на вероятность оттока:

- Положительный вес → признак увеличивает вероятность оттока.
- Отрицательный вес → признак снижает вероятность оттока.
- Вес близкий к 0 → признак не важен.

В sklearn веса доступны через `model.coef_`:

    from sklearn.linear_model import LogisticRegression

    model = LogisticRegression()
    model.fit(X_train, y_train)

    # Веса для каждого признака
    weights = model.coef_[0]
    for name, w in zip(X_train.columns, weights):
        print(f"{name}: {w:+.3f}")

В нашем курсе мы ожидаем увидеть:
- `стаж_месяцев` → большой отрицательный вес (чем больше стаж, тем меньше отток).
- `жалобы_12мес` → большой положительный вес (чем больше жалоб, тем выше отток).
- `просрочки_платежей_12мес` → положительный вес.

Если веса совпадают с ожиданиями — значит, модель «поняла» данные. Если нет — что-то пошло не так на этапе подготовки.

## Класс weight='balanced'

В прошлом уроке мы говорили о дисбалансе классов. Логистическая регрессия поддерживает параметр `class_weight='balanced'`, который автоматически даёт ушедшим клиентам больший вес (в ~3 раза, пропорционально соотношению классов).

Без этого параметра модель будет склоняться к предсказанию «не уйдёт» для большинства клиентов.

    model = LogisticRegression(class_weight='balanced')

## Ограничение: только линейная зависимость

Логистическая регрессия может уловить только **линейные** зависимости. Она не умеет в квадраты, взаимодействия признаков и нелинейные связи.

Например, зависимость «чем больше возраст, тем выше отток, но только до 60 лет, а потом снова падает» — она не увидит.

Именно поэтому в следующих уроках мы попробуем деревья и бустинг, которые умеют работать с нелинейностью.

## Российский контекст

В телекоме логистическая регрессия — это «рабочая лошадка» для быстрых пилотов. Многие российские операторы используют её как baseline для оценки того, стоит ли вообще заморачиваться с ML.

Если после логистической регрессии модель показывает ROC-AUC > 0.75 — значит, данные хорошие, и есть смысл обучить бустинг. Если < 0.6 — скорее всего, с признаками что-то не так.
