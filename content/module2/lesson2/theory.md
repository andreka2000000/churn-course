# Урок 2.2 — Кодирование категорий

## В чём проблема?

В первом модуле мы увидели, что в датасете есть колонки со строками: пол, тариф, тип договора, регион, технология интернета.

Проблема в том, что **ни одна ML-модель не работает со строками**. Модель — это математика. Она умеет умножать, складывать и сравнивать числа. Строку «Женат» нельзя умножить на коэффициент 0.5.

Значит, все строки надо превратить в числа. Этот процесс называется **кодированием категорий**.

## Способ 1: Label Encoding (порядковое кодирование)

Самый простой способ: каждой категории даём свой номер.

    Женат/Замужем → 0
    Холост/Не замужем → 1

    Мини → 0
    Смарт → 1
    Смарт+ → 2
    Ультра → 3
    Премиум → 4

В коде:

    from sklearn.preprocessing import LabelEncoder

    le = LabelEncoder()
    df['пол_код'] = le.fit_transform(df['пол'])

**Когда работает:** если категории **действительно упорядочены**. Тарифы — да, у них есть логика от «дешевле» к «дороже». А вот пол — нет. Если сказать модели, что «Ж = 1, а М = 0», она решит, что женщина «больше» мужчины — и будет искать связь «чем больше пол, тем больше отток». Это абсурд.

**Главный минус:** модель начнёт искать линейную зависимость там, где её нет. Поэтому Label Encoding используется только для упорядоченных категорий.

## Способ 2: One-Hot Encoding (создание бинарных колонок)

Второй способ — создать **отдельную бинарную колонку для каждой категории**.

Допустим, у нас колонка `тип_договора` с тремя значениями: Безсрочный, 1 год, 2 года.

После One-Hot Encoding получится три колонки:

    тип_договора_Безсрочный | тип_договора_1_год | тип_договора_2_года
    ----------------------- | ------------------ | -------------------
              1             |         0          |         0
              0             |         1          |         0
              0             |         0          |         1

Теперь в каждой строке ровно одна единица. Модель видит: «если `тип_договора_2_года = 1`, то это двухлетний договор». Никаких «больше-меньше» — просто флаг.

В pandas это делается одной строкой:

    df_encoded = pd.get_dummies(df, columns=['тип_договора', 'способ_оплаты', 'регион'])

Параметр `columns` указывает, какие колонки кодировать. Все остальные останутся как были.

**Когда работает:** для любых номинальных категорий (пол, тип договора, регион, тариф).

**Главный минус:** при большом количестве категорий получается слишком много новых колонок. Например, если у вас 1000 городов — получите 1000 новых колонок. Это называется **проклятием размерности**.

## Способ 3: Target Encoding (кодирование средним оттоком)

Третий способ — самый хитрый. Мы заменяем каждую категорию на **средний отток внутри этой категории**.

    Москва → 0.32 (32% клиентов уходят)
    СПб → 0.28
    Регионы → 0.18

Теперь колонка `регион` превратилась в числовую: «вероятность оттока для этого региона».

В коде:

    means = df.groupby('регион')['отток'].mean()
    df['регион_te'] = df['регион'].map(means)

**Когда работает:** когда категорий много и One-Hot даст слишком много колонок. Особенно хорошо для регионов, тарифов.

**Главный минус:** **data leakage**. Если считать средний отток по всей выборке, то в признак попадает информация из целевой переменной. Модель на тренировке будет «подглядывать в ответ» и покажет идеальные метрики, а на новых данных — плохие.

**Правильно:** считать Target Encoding **только на тренировочной выборке** (об этом — в уроке 2.5) и применять на тест.

## Что выбрать?

Правило простое:

- **Мало категорий (2–10)** → One-Hot Encoding
- **Упорядоченные категории (тарифы)** → Label Encoding
- **Много категорий (10+)** → Target Encoding, но осторожно

В нашем датасете:

| Колонка | Категорий | Способ |
|---|---|---|
| пол | 2 | One-Hot |
| семейное_положение | 2 | One-Hot |
| тип_договора | 3 | One-Hot |
| способ_оплаты | 4 | One-Hot |
| технология_интернета | 3 | One-Hot |
| регион | 6 | One-Hot (или Target Encoding) |
| тариф | 5 | Label Encoding (упорядочен) |

## Как не сломать пайплайн

Одна из типичных ошибок — закодировать **все** категориальные колонки через `pd.get_dummies`, не задумываясь. На выходе получается 50+ колонок, многие из которых — почти константы (одна единица на 7000 нулей). Это бесполезный шум.

Правило: **не кодируйте колонки, которые не имеют смысла для предсказания.** `id_клиента` — это идентификатор, он ничего не говорит о клиенте. Просто удалите его.
