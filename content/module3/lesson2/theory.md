# Урок 3.2 — Метрики классификации

## Почему Accuracy не работает

В прошлом уроке мы обучили логистическую регрессию. Если посчитать Accuracy (долю правильных ответов), мы получим около 75%. Звучит неплохо!

Но давайте вспомним урок 2.4. Если модель просто скажет «все останутся», она уже угадает 74% (потому что 74% клиентов не уходят). Значит, наша модель с Accuracy 75% едва лучше «тупого» правила.

Accuracy не различает, **кого именно** модель не угадала. Ошиблась на лояльном клиенте — не страшно. Ошиблась на уходящем — упустили деньги.

Чтобы понять, насколько модель полезна бизнесу, нужны другие метрики.

## Confusion Matrix (Матрица ошибок)

Всё начинается с таблицы 2×2, которая показывает 4 типа предсказаний:

                      Предсказано 0   Предсказано 1
    Реально 0 (TN)    True Negative   False Positive
    Реально 1 (FN)    False Negative  True Positive

Расшифровка:
- **TN (True Negative)** — клиент остался, и модель сказала «останется». Правильно.
- **FP (False Positive)** — клиент остался, а модель сказала «уйдёт». Ложная тревога.
- **FN (False Negative)** — клиент ушёл, а модель сказала «останется». **Самая дорогая ошибка** — мы его не удержали.
- **TP (True Positive)** — клиент ушёл, и модель это предсказала. Правильно, успели удержать.

В коде:
    from sklearn.metrics import confusion_matrix
    cm = confusion_matrix(y_test, y_pred)
    print(cm)

## Precision и Recall

Из матрицы ошибок получаются две ключевые метрики.

### Precision (Точность)

    Precision = TP / (TP + FP)

«Из всех, кого модель назвала уходящими, сколько реально ушли?»

Высокий Precision значит: модель **редко ошибается**, когда предсказывает отток. Если Precision = 0.8, то из 10 предсказанных уходов 8 — реальные.

Важно, когда бизнес платит за каждое удержание (звонок клиенту, скидка). Если зря позвонить 100 людям — потеряем деньги на удержание лояльных.

### Recall (Полнота)

    Recall = TP / (TP + FN)

«Из всех, кто реально ушёл, сколько модель смогла найти?»

Высокий Recall значит: модель **находит большинство** уходящих. Если Recall = 0.8, то из 100 реальных уходов модель поймала 80.

Важно, когда пропустить уход дороже, чем лишний раз позвонить.

## F1-score: баланс между ними

Precision и Recall конфликтуют. Можно получить Precision = 1.0, если модель предсказывает «уйдёт» только 1 раз и угадывает. Но тогда Recall будет близок к 0.

F1-мера — это гармоническое среднее Precision и Recall:

    F1 = 2 * (Precision * Recall) / (Precision + Recall)

Хороший F1 значит, что обе метрики высокие одновременно.

## ROC-AUC: главная метрика

ROC-кривая показывает, как меняется соотношение True Positive Rate (Recall) и False Positive Rate при изменении порога классификации (от 0 до 1).

**AUC** (Area Under Curve) — площадь под этой кривой. Значение от 0 до 1:
- **AUC = 0.5** — модель ничем не лучше случайного угадывания.
- **AUC = 0.7–0.8** — приемлемо.
- **AUC = 0.8–0.9** — хорошо.
- **AUC > 0.9** — отлично (но часто означает data leakage).

В коде:
    from sklearn.metrics import roc_auc_score
    auc = roc_auc_score(y_test, y_proba)
    print(f"ROC-AUC: {auc:.4f}")

`y_proba` — это **вероятности**, а не бинарные предсказания. Получить их можно через `pipe.predict_proba(X_test)[:, 1]`.

## Какую метрику выбрать

Всё зависит от бизнес-задачи:
- **Хотим не беспокоить лояльных клиентов** → важнее Precision.
- **Хотим поймать всех уходящих любой ценой** → важнее Recall.
- **Баланс** → F1.
- **Общее качество модели** → ROC-AUC.

В нашем курсе основной метрикой будет **ROC-AUC**. Он не зависит от порога, работает с вероятностями, легко сравнивать модели.
