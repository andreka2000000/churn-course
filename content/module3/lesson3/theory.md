# Урок 3.3 — Decision Tree и Random Forest

## Проблема логистической регрессии

В уроке 3.1 мы обучили логистическую регрессию. Она работает неплохо, но имеет серьёзное ограничение: она **линейная**. Модель ищет только прямые зависимости вида «чем больше X, тем больше вероятность оттока».

А реальный мир нелинеен. Например:
- Молодые клиенты (18–25) уходят часто, средний возраст (35–50) — лоялен, а пожилые (60+) — снова уходят часто. Это U-образная зависимость.
- Клиенты с очень низким платежом уходят часто (нет смысла оставаться), и с очень высоким — тоже (ищут премиум у конкурентов). Средний сегмент — лоялен.

Логистическая регрессия такие зависимости не увидит.

## Что такое Decision Tree

**Дерево решений** (Decision Tree) — это модель, которая работает как серия вопросов «да/нет».

Пример для оттока:

    ┌─────────────────────────────┐
    │ Тип договора = Безсрочный?  │
    └──────────┬──────────────────┘
               │
       ┌───────┴────────┐
       │                │
      ДА               НЕТ
       │                │
    ┌──▼──────────┐  ┌──▼───────┐
    │ Отток: 85%  │  │ Отток: 5%│
    └─────────────┘  └──────────┘

Модель задаёт клиенту вопросы: «Тип договора — безсрочный?», «Стаж меньше 6 месяцев?», «Есть ли жалобы?». По ответам она идёт по дереву и в итоге попадает в «лист» — конечный узел, где записан процент оттока для похожих клиентов.

Каждый вопрос — это **split** (разбиение). Дерево автоматически подбирает, какой признак и какой порог лучше всего разделяют классы.

## Как дерево выбирает разбиения

Для каждого признака и каждого порога дерево считает, насколько хорошо после этого разбиения классы становятся «чистыми» (в одной группе больше ушедших, в другой — больше оставшихся).

Мера «чистоты» называется **Gini impurity** или **энтропия**. Чем меньше impurity, тем лучше разбиение. Дерево жадно выбирает разбиение с минимальной impurity на каждом шаге.

## Проблема переобучения

Дерево может «выучить» тренировочные данные наизусть. Если не ограничивать глубину, оно создаст узел для **каждого клиента** — и на тесте покажет ужасный результат.

Признаки переобучения:
- Высокая accuracy на train (> 95%), низкая на test.
- Дерево очень глубокое (десятки уровней).

Решения:
- **`max_depth`** — максимальная глубина дерева (например, 5–10).
- **`min_samples_leaf`** — минимум клиентов в листе (например, 20–50).
- **`min_samples_split`** — минимум клиентов в узле для разбиения (например, 40–100).

Эти параметры называются **гиперпараметрами** — их не обучают, их задаёт инженер.

## Random Forest: лес вместо одного дерева

Одно дерево — хрупкая модель. Чуть изменились данные — дерево полностью поменялось. Это называется «высокая дисперсия».

Решение — **Random Forest** (Случайный лес). Идея:
1. Обучить **100–500 деревьев** на разных случайных подвыборках данных.
2. Обучить каждое дерево на **разных подмножествах признаков** (например, на 70% случайных фич).
3. Усреднить предсказания всех деревьев.

Почему это работает: каждое дерево ошибается по-своему, но при усреднении ошибки компенсируются. Это называется **бэггинг** (bagging = bootstrap aggregating).

Random Forest почти всегда лучше одиночного дерева: меньше переобучается, стабильнее, показывает лучшие метрики.

## Плюсы и минусы

### Decision Tree

Плюсы:
- Легко интерпретировать (можно нарисовать дерево).
- Не требует масштабирования (инвариантно к масштабу).
- Работает с категориями.

Минусы:
- Сильно переобучается.
- Нестабилен (маленькое изменение данных ломает дерево).

### Random Forest

Плюсы:
- Высокое качество «из коробки».
- Устойчив к переобучению.
- Даёт feature importances (важность признаков).

Минусы:
- Медленнее обучается.
- Сложнее интерпретировать (нет одного «дерева решений»).
- Занимает много памяти (сотни деревьев).

## Российский контекст

Random Forest — популярный baseline в российском финтехе и телекоме. Он простой, быстрый и показывает стабильные 0.80–0.85 ROC-AUC на табличных данных.

Но в последние годы CatBoost (от Яндекса) обошёл его по качеству — об этом в следующем уроке.
